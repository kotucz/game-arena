# Web Push Implementation Summary

## Goal
Enable browser push notifications for web clients using the Web Push API, with service-worker based delivery and VAPID authentication.

## What was implemented

### 1. Web client subscription flow
- `app/webApp/src/webMain/resources/pwa.js`
  - Registers the app service worker at `/sw.js`.
  - Requests Notification permission when available.
  - Reads the VAPID public key from `/api/notifications/vapidPublicKey`.
  - Subscribes with `PushManager.subscribe({ userVisibleOnly: true, applicationServerKey })`.
  - Stores a stable client-generated `tokenId` in `localStorage` so the browser can refresh or delete its own registration safely.
  - Sends the subscription JSON to the server using the existing notification-token endpoint:
    - `PUT /api/notifications/tokens/{tokenId}`
    - body: `{ "service": "webpush", "token": "<subscription-json>" }`

### 2. Service worker push handling
- `app/webApp/src/webMain/resources/sw.js`
  - Added `push` event listener to display incoming browser notifications.
  - Added `notificationclick` handler so users can open the app when they tap a browser notification.

### 3. Server-side VAPID configuration
- `server/src/main/kotlin/cz/kotu/gamearena/ServerConfig.kt`
  - Added optional `vapidPublicKey` and `vapidPrivateKey` fields.
- `server/src/main/resources/application.conf`
  - Added `gamearena.webpush.publicKey` and `gamearena.webpush.privateKey` placeholders.
- `server/src/main/kotlin/cz/kotu/gamearena/Application.kt`
  - Exposes public key via:
    - `GET /api/notifications/vapidPublicKey`

### 4. Push delivery backend
- `server/src/main/kotlin/cz/kotu/gamearena/WebPushNotificationService.kt`
  - Sends web-push messages using `nl.martijndwars:web-push`.
  - Parses stored subscription JSON from DB.
  - Uses VAPID keys and `PushService` to deliver notifications.
  - Deletes stale tokens if browser subscriptions return 404/410-style failures.
- `server/src/main/kotlin/cz/kotu/gamearena/CompositePushNotificationService.kt`
  - Combines FCM and webpush delivery.
- `server/src/main/kotlin/cz/kotu/gamearena/ServerBindings.kt`
  - Wires the composite notification service into DI.

### 5. Dependency and security fix
- `server/build.gradle.kts`
  - Added `nl.martijndwars:web-push` dependency.
  - Added BouncyCastle provider dependency (`bcprov-jdk18on`) because the web-push library requires it for EC key handling.

### 6. Tests
- `server/src/test/kotlin/cz/kotu/gamearena/WebPushTest.kt`
  - Verifies a webpush registration can be stored.
  - Verifies the web-push service does not blow up when VAPID keys are missing.

## Data flow
1. Browser asks for notification permission.
2. Browser creates a push subscription with the browser push service.
3. Browser sends the subscription JSON to the server using the existing `tokenId` endpoint.
4. Server stores it in `push_tokens` keyed by client-generated `tokenId` and scoped to the authenticated username.
5. When the app sends a notification, the server fetches webpush tokens for the target users and delivers via the Web Push protocol using VAPID.
6. If the browser subscription is invalid or expired, the token is deleted lazily.

## Important notes
- The VAPID private key must be the raw URL-safe base64 key generated by a web-push-compatible tool, not a PEM block.
- The public key is safe to expose to the browser.
- Private keys should be stored outside source control, ideally via `GAMEARENA_CONFIG` or another secret store in production.
- This implementation reuses the existing authenticated token registration endpoint rather than adding a separate server-local contract.

## Generating and configuring VAPID keys

Use a standard web-push key generator, then paste only the raw public/private strings into the HOCON config.

Example:

```bash
npx web-push generate-vapid-keys
```

This prints output similar to:

```text
Public Key: BEl...
Private Key: 1p...
```

Put the values into `server/src/main/resources/application.conf`:

```hocon
gamearena {
  webpush {
    publicKey = "BEl..."
    privateKey = "1p..."
  }
}
```

Do not store PEM-style blocks such as:

```text
-----BEGIN PRIVATE KEY-----
...
-----END PRIVATE KEY-----
```

Those are not the formats expected by `nl.martijndwars:web-push`.

For production, prefer `GAMEARENA_CONFIG` or an environment/secrets mechanism instead of keeping the private key in source-controlled config files.

## Quick browser verification checklist

1. Start the server with valid VAPID keys configured.
2. Open the web app in a browser on localhost or HTTPS.
3. Accept notification permission when prompted.
4. Confirm the browser registers a push subscription and the server stores it in `push_tokens`.
5. Trigger an app notification from the server.
6. Verify the browser displays the push notification and clicking it opens the app.
